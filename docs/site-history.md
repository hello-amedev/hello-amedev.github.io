### 効かなかった手法と、その理由

- **radial-gradient の長い減衰でメッシュを作る** → 機械的に見える。
  縁の溶け幅が形の大きさに比例してしまい、参考画像の「形が見えるのに柔らかい」
  質感が出ない。**輪郭のある色面を `filter: blur()` でぼかす**方式に変えて解決
- **グレインを `mix-blend-mode: overlay / soft-light` で乗せる** → 白地では
  数学的にほぼ無効(基底が 1 に近いと結果も 1 のまま)。**ノイズの明度を
  アルファに変換した「墨の粒」を通常合成でまぶす**方式に変えて解決
- **アイコンの厚みを「ひと回り大きい層」で作る** → 枠が浮いて格好悪い。
  **板 = アイコンそのもの**にして、下端の接地影 1 本だけで厚みを示す形に
- **アイコンを大きく傾ける(±13〜31°)** → 正方形が潰れて「圧縮された板」に
  見える。**±5〜11°** まで落とし、マウス追従も 9° → 2.5° に
- **AI for ART を不透明度のフェードで出し入れ** → 急に現れて急に消える。
  **紙 → 闇の切り替えを「一気に反転」**させ、出口では戻さない形に
- **白 → 黒のグラデーション帯で世界を繋ぐ** → 安っぽい。廃止

### ハマった不具合

- **カード本文にアクセント色の帯が乗る**
  主力カードのコンテナと通常カードの本文が、どちらも `.hb-card-lead` という
  同じクラス名だった。コンテナ側の背景グラデーションが本文に適用されていた。
  → 主力カード側を `.hb-feature*` に改名して解消
- **ホバーで主力カードのグラデーションが消える**
  ホバー時に `background` の**一括指定**を使っていたため、`background-image` の
  グラデーションごと消えていた。→ `background-color` だけを触る形に
- **AI for ART の背景がページ最下部まで貼り付く**
  背景を重ねるのに負のマージンを使い、sticky の可動範囲の計算が壊れていた。
  → 絶対配置のラッパー(`.hb-art-bgwrap`)で重ねる形に
- **作品の背景に動かない光の筋が焼き付いて見える**
  実物(動く iframe)の下に「育った状態の静止画」を敷いたままだったため。
  → 実物が乗ったら静止画を 4 秒かけて完全に溶かして消す
- **スクショが枠の高さに対する % 指定で縮まない**
  枠の高さが `aspect-ratio` 由来だと、% 高さが解決されず原寸で描画される
  エンジンがある。→ 幅と margin の %(必ず幅基準で解決される)だけで
  大きさと位置を決める形に

### 検証環境の落とし穴(次回もハマる)

Claude Code のブラウザペインが非表示のとき、**rAF・IntersectionObserver・
CSS トランジション・スムーススクロールがすべて凍る**。このため:

- スクロール連動やホバーの色変化を `getComputedStyle` で読むと、
  **開始値のまま**返ってくる。判定を誤りやすい
- 対策: 検証中だけ `transition:none` を注入する / `requestAnimationFrame` を
  同期実行に差し替える / `scroll-behavior:auto` にする
- headless Chrome 側は rAF も IO も動くが、**フラグメント(`#works`)への
  スクロール撮影は composite がずれて使い物にならない**。
  全体像を撮る時は、撮影中だけ `100svh` を固定 px に置換するのが確実

## 確立した方針(現在も有効)

### Drive DAM LP

1. **カード内での「画面の一部を覗く」演出は縁接続型で**。全体を見せたい時は
   薄青パネル + 浮かせるモーダル型、一部を切り出す時は**カード縁で切れる**構図
2. **カード比率は正方形 1:1 を主軸に**。横長画像は幅 1/2 段で対比配置
3. **図解の線画言語**: 墨 1.4px ストローク + 青(`#4A7CE2`)/ 赤(`#B5544A`)
   アクセント + グレー(`#8B887F`)のラベル文字
4. **カテゴリ見出し**: 青いドット + 日本語(20〜28px)
5. **ロゴ再現度の基準**: 参考画像のデフォルメ形状を線画で**構造まで再現**
6. **「そのほかの機能」の締めはワイドバンドで**

### 全体

- 「実アプリ画面が見えるかどうか」を第一の品質ゲートに
- 両極端を避ける(淡々シンプル vs 個性的比喩)
- 製品画面のビジュアル化は「実スクショ or 完全再現」の二択、中間 NG
- **デザイン制作はメインモデルが直接**(エージェント委譲は平均に収束することが
  実測 2 回で判明)
